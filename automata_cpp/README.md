# 编译原理：正规式、NFA、DFA 与最小化 DFA 的 C++17 转换程序

提供 **6 个可执行程序**，覆盖四种表示之间的转换。采用竞赛常用的邻接表、动态 bitset、哈希判重、SCC、CSR 逆边和较小分块优化，同时包含严格输入校验、资源限制和随机对拍。

推荐先运行 `regex_to_min_dfa`，再按步骤阅读算法。`standalone/` 中每个 `.cpp` 都是完整单文件，可以直接复制、编译；项目根目录的同名程序共享 `include/`，便于学习和修改。单文件由 `make_single.py` 生成，修改共享代码后应重新生成。

## 1. 程序与转换范围

| 程序 | 输入 → 输出 | 方法 |
|---|---|---|
| `regex_to_nfa` | 正规式 → ε-NFA | 迭代表达式解析 + Thompson 构造 |
| `nfa_to_dfa` | ε-NFA / 无 ε 边 NFA → 完整 DFA | ε-SCC 压缩 + 动态 bitset + 子集构造 |
| `dfa_minimize` | 完整或部分 DFA → 完整最小 DFA | 可达性裁剪 + 补死状态 + Hopcroft |
| `automaton_to_regex` | NFA / DFA / 最小 DFA → 正规式 | 稀疏 GNFA 状态消元 |
| `regex_to_min_dfa` | 正规式 → 完整最小 DFA | 前三步串联 |
| `dfa_to_nfa` | DFA / 最小 DFA → NFA | 将确定转移表示为 NFA 边 |

NFA → 最小 DFA：串联第二、第三个程序。正规式 → DFA：串联第一、第二个程序。最小 DFA 本身就是 DFA，DFA 本身也属于 NFA；这些方向不需要新的理论构造。

本文中的 NFA 允许 ε 边、重复边、多终态、没有终态和 ε 环，只有一个初态。多个初态可用新初态的 ε 边连接。

## 2. 编译与运行

使用 GCC 或 Clang 的 C++17 模式。最低位枚举使用 `__builtin_ctzll`，因此本版本不直接支持 MSVC；Windows 可使用 MinGW-w64 或 llvm-mingw。

最方便的单文件编译：

```sh
g++ -std=c++17 -O2 -Wall -Wextra -Wpedantic standalone/regex_to_min_dfa.cpp -o regex_to_min_dfa
```

也可在项目目录编译共享版本，其他程序同理：

```sh
g++ -std=c++17 -O2 regex_to_min_dfa.cpp -o regex_to_min_dfa
```

Linux / macOS 的 shell：

```sh
echo '(a|b)*abb' | ./regex_to_min_dfa
```

Windows PowerShell（单引号保留正规式中的反斜杠）：

```powershell
'(a|b)*abb' | .\regex_to_min_dfa.exe
```

批量编译及核心测试：

```sh
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build -j 4
ctest --test-dir build --output-on-failure
python tests/test_cli.py build
```

Windows MinGW 首条改为 `cmake -S . -B build -G "MinGW Makefiles" -DCMAKE_BUILD_TYPE=Release`。多配置生成器的可执行文件通常位于 `build/Release`，CLI 测试应传实际目录。

PowerShell 中演示完整链：

```powershell
'(a|b)*abb' | .\build\regex_to_nfa.exe | .\build\nfa_to_dfa.exe | .\build\dfa_minimize.exe
Get-Content examples/epsilon_nfa.txt | .\build\nfa_to_dfa.exe
Get-Content examples/partial_dfa.txt | .\build\dfa_minimize.exe
Get-Content examples/epsilon_only_dfa.txt | .\build\automaton_to_regex.exe
```

所有程序从标准输入读取，转换结果写标准输出。错误写标准错误并返回退出码 1；成功返回 0。调用脚本应检查每个进程的退出码；附带 CLI 测试通过 `subprocess` 检查，避免 shell 管道隐藏前序错误。生成的自动机文本及正规式输出均为 ASCII，便于跨平台传递。

## 3. 正规式语法

| 写法 | 含义 | 示例 |
|---|---|---|
| 普通字节 | 对应字面符号 | `a`、`0` |
| `AB` 或 `A.B` | 连接 | `ab`、`a.b` |
| `A\|B` | 并 | `a\|b` |
| `A*` | 零次或多次 | `a*` |
| `A+` | 一次或多次 | `a+` |
| `A?` | 零次或一次 | `a?` |
| `(A)` | 分组 | `(a\|b)*` |
| `@` | 空串 ε | `a\|@` |
| `#` | 空语言 ∅ | `#` |
| `\c` | 将下一个字节当字面符号，`x` 除外 | `\*`、`\.`、`\@`、`\\` |
| `\xHH` | 十六进制字节，恰好两位 | `\x20` 空格、`\x00`、`\xFF` |

优先级：后缀 `* + ?` > 连接 > 并；连接和并按左结合处理。允许连续后缀运算，例如 `a*?` 表示 `(a*)?`，**不是**正则引擎的非贪婪匹配。空白在未转义时忽略，因此 `a b` 与 `ab` 等价。空输入、`()`、`a|` 等属于语法错误；空串必须写 `@`。

这是形式语言课程中的字节正规式：`.` 是连接，`+` 是后缀正闭包；不提供通配点、字符类、范围、锚点、计数重复和反向引用。`[a-z]`、`^`、`$`、`{2}` 中的非运算符字节按字面值处理。`\n` 表示字母 n；换行应写 `\x0A`。中文 UTF-8 输入会作为多个字节处理，不会把一个汉字当一个原子符号。常用的有限字符类可自行展开，例如 `[0-2]` 的意图应写成 `(0|1|2)`。

## 4. 统一自动机格式

状态从 **0** 开始编号。字母表每个元素均用两位十六进制表示：`61` 是字符 a，`62` 是 b，`30` 是数字字符 0，`00` 是 NUL。十六进制不带 `0x` 前缀，不区分大小写。

输入按空白分隔，换行仅用于阅读。空字母表、空终态集合对应的行可以为空。初态、终态、转移编号都会检查；多余 token、重复字母表、重复终态会报错。不支持注释。

### NFA

```text
NFA
n k s f m
k 个字母表字节
f 个终态编号
接下来 m 行：起点 终点 标签
```

`n` 为状态数，`k` 为字母表大小，`s` 为初态，`f` 为终态数量，`m` 为边数。边标签是 `eps` 或字母表中的两位十六进制字节。

例如 `examples/epsilon_nfa.txt` 表示 `a*b|@`：

```text
NFA
4 2 0 1 5
61 62
3
0 1 eps
1 1 61
1 2 62
2 3 eps
0 3 eps
```

### DFA

```text
DFA
n k s f
k 个字母表字节
f 个终态编号
接下来 n 行，每行 k 个转移目标
```

第 u 行第 c 列表示 `δ(u, alphabet[c])`。目标 `-1` 表示缺失转移，读到该转移立即拒绝。算法输出的 DFA 为完整 DFA，必要时包含显式拒绝死状态。

`(a|b)*abb` 的最小 DFA 输出如下，恰有 4 个状态：

```text
DFA
4 2 0 1
61 62
3
1 0
1 2
1 3
1 0
```

状态 0、1、2、3 分别记录当前串后缀与 `abb` 的前缀匹配了 0、1、2、3 个字符。只有状态 3 接受；本语言无需额外死状态。

字母表顺序在 NFA/DFA 转换中保留。正规式解析的字母表按字面字节首次出现顺序建立。转回正规式后再解析，未使用的字母可能消失、顺序可能变化，但语言不变。语言相等时不应直接假设状态编号或转移表文本相同。

## 5. 算法、优化与正确性要点

### 正规式 → NFA：Thompson

入口为 `include/regex.hpp` 的 `regex_to_nfa`。使用运算符栈和片段栈完成解析，片段只记录入口、出口；不建立额外语法树。

- 字面符号建立一条符号边，`@` 建立 ε 边，`#` 建立无通路的两端。
- 连接用 ε 边连接两个片段；并联和重复构造新入口、出口。
- 每种构造都保持“入口到出口的路径标签集合等于该子表达式语言”。按表达式结构归纳，即得正确性。
- 全程迭代；深层括号、长连接链不会依赖递归调用栈。长度为 L 时，时间和空间均为 O(L)。

### NFA → DFA：ε-SCC + 动态 bitset 子集构造

入口为 `include/core.hpp` 的 `determinize`。`Bits` 使用 `vector<uint64_t>`，相当于运行时长度的 `std::bitset`，避免编译期 `MAXN` 限制。

1. 删去初态不可达部分，再用**迭代 Kosaraju**压缩 ε 边强连通分量。同一分量中的状态互相 ε 可达，闭包总是同时包含它们。
2. ε 分量构成 DAG；按逆拓扑序用整字 OR 计算每个分量的 ε 闭包。
3. DFA 初态为 `ε-closure({s})`。对闭包集合 S 和字母 a，计算：

   `next(S,a) = ε-closure( ⋃ { NFA-move(q,a) : q ∈ S } )`。

4. 用哈希表给不同集合分配整数编号，只拓展从初态实际可达的子集；终态判定是集合与 NFA 终态掩码是否相交。
5. 空子集也是合法状态，必要时自动成为拒绝死状态。

优化细节：`ctzll` 与 `x &= x-1` 只枚举置位，且只对非零机器字调用 `ctzll`；ε-DAG 和符号转移去重；只存非空的“分量、字母”转移；多目标闭包可按预算缓存，预算耗尽后即时 OR，结果不变；哈希比较完整 bitset，哈希碰撞不会合并不同状态。哈希表键只保存一份集合，BFS 保存其稳定指针，降低重复存储。向量扩容之后才写 DFA 行，避免悬空引用。

正确性不变量：读取任意输入串 w 后，DFA 状态精确表示 NFA 读取 w 后所有可能位置的 ε 闭包。由上述转移公式和终态交集判定，两个自动机接受完全相同的语言。

设 C 为可达 ε-SCC 数，W=⌈C/64⌉，D 为实际 DFA 状态数，k 为字母表大小，Eε 为压缩后的 ε-DAG 边数，Es 为去重后的符号边数：

- SCC 遍历 O(n+m)，边排序另计，最坏可用 O(m log(m+1)) 上界。
- ε 闭包预处理 O((C+Eε)W)。
- 子集阶段保守期望上界 O(D·[kC log(k+1)+(Es+k)W])；缓存和稀疏集合通常可减少实际工作量。哈希是期望性能，不是严格最坏保证。
- 主要存储 O(n+m+(C+D+B)W+Dk)，B 为缓存 bitset 数量。

**不能把整体时间写成 O(n²) 或 O(DkC/64)：D 最坏仍可能指数增长，且必须计算符号边的并集。** bitset 加速集合运算，不会消除自动机确定化的指数下界。

### DFA → 最小 DFA：真正的 Hopcroft 分区细化

入口为 `include/minimize.hpp` 的 `minimize_dfa`。

- BFS 去除不可达状态，并按缺失转移的拒绝语义补齐死状态。
- 按终态、非终态建立初始分区。
- 使用 CSR 逆边快速取得分割集合的前驱；工作队列按较小分块原则维护。
- 所有状态保存在同一个排列数组中，块对应连续区间，位置数组支持 O(1) 交换；按被标记状态移动，不反复扫描整个大块。
- 先收集完整逆像，再分割各块，处理分割器自身被分裂的情况。
- 最后将稳定分区构造成商自动机，并按字母表顺序 BFS 重新编号，初态为 0。

最终同一块内的状态具有相同终态性质，且对每个字母转入同一块。分割只区分未来行为不同的状态；稳定分区中的不同块可被某个后缀区分，因此可达商自动机最小。

以输入状态数 n 和字母表大小 k 计，时间 O(n+kn log(n+1))、空间 O(n+kn)。输出是在**给定字母表上的完整最小 DFA**；如果某教材允许省略死状态的部分 DFA，显示的状态数可能少一个，两者约定不同。

### NFA / DFA → 正规式：稀疏 GNFA 状态消元

入口为 `include/regex.hpp` 的 `nfa_to_regex`。DFA 通过 `as_nfa` 进入同一实现，不要求先最小化；较大的 DFA 可先最小化以降低消元规模。

新增独立起点 S、终点 T，原初态前及各终态后连接 ε 边。消去状态 k 时，更新所有前驱 i、后继 j：

`R[i][j] ← R[i][j] | R[i][k] (R[k][k])* R[k][j]`。

公式分别覆盖不经过 k 和经过 k 任意多次的路径，保持剩余状态间的路径语言。全部原状态消去后，S→T 的标签即答案。

实现会删除不能从起点到达或不能通向终态的状态；用稀疏图保存非空标签，按入度×出度选择消元点；标签使用哈希驻留的表达式 DAG，避免不断复制长字符串；应用 `∅|R=R`、`εR=R`、`∅R=∅`、`R|R=R`、`∅*=ε` 等化简。最终以迭代方式输出并按优先级补括号、转义字面符号。

最坏 O(N³) 次标签组合，优先队列维护另有对数开销；标签 DAG 节点数可达 O(m+N³)。展开后的正规式长度可能指数增长。消元顺序只是控制膨胀的启发式，**不保证最短正规式**。

## 6. 参数与明确的规模限制

| 程序 | 参数及默认值 |
|---|---|
| `regex_to_nfa` | `--max-states 1000000`，NFA 状态数上限 |
| `nfa_to_dfa` | `--max-states 200000 --bitset-mib 256 --cache-mib 64` |
| `regex_to_min_dfa` | 上一行参数，加 `--max-nfa-states 1000000` |
| `automaton_to_regex` | `--max-nodes 1000000 --max-output 1000000` |

参数使用独立的十进制值，例如 `--max-states 500000`；不支持 `--max-states=500000`。无选项的两个程序不接受额外参数。

`--bitset-mib` 限制 ε 闭包、子集键和临时掩码的原始 64 位数据；`--cache-mib` 是独立的转移闭包缓存预算，设为 0 即禁用缓存。**这些不是进程总内存上限**：邻接表、转移表、容器节点和分配器开销另计。增大状态上限也不会自动增大 bitset 预算。

`--max-nodes` 分别限制表达式 DAG 节点数和当前 GNFA 边数；`--max-output` 限制正规式正文的输出字节数，不含结尾换行。超限会报错，不会返回不等价的截断结果。极小预算即使处理简单输入，也可能不足以保存基本节点。

CLI 另设输入上限：正规式文本 1,000,000 字节；自动机 1,000,000 状态；字母表最多 256 字节；NFA 边数及 DFA 表格单元各最多 256,000,000。它们是格式读取的保护限制，具体见 `cli.hpp`、`io.hpp`，可按机器能力修改。提高生成器参数可能产生超过下一程序读取上限的文件；百万状态的部分 DFA 补死状态也可能多一个状态，需相应调整读取常量。系统内存不足等异常也会报告失败。

所有转换均保持语言；“完整性”指所定义语法和自动机模型下的转换与边界处理，不表示任意规模输入均能在有限内存内完成。

## 7. 测试与源码阅读顺序

`tests/test_automata.cpp` 使用固定随机种子，包含独立的逐步 ε-NFA 模拟、独立子集构造、DFA 乘积 BFS 精确等价性检查及表填充最小状态数检查；并有正规式往返、空集、空串、ε 环、多终态、部分转移、不可达状态、跨 64 位集合、缓存关闭和资源限制用例。小长度穷举只作为补充，语言等价性的主要判断使用完整乘积图。

`tests/test_cli.py` 检查真实可执行文件的串接、输出格式、选项和错误输入。最新实际验证记录见 `TEST_REPORT.md`。

建议阅读顺序：`regex.hpp::regex_to_nfa` → `core.hpp::Bits` / `determinize` → `minimize.hpp` → `regex.hpp::nfa_to_regex`。共享实现与单文件版本功能一致。
